Three kinds of evidence — kept separate on purpose

Tested Equivalent on tested inputs

Both algorithms run on the same generated inputs (edge cases + seeded random inputs for every input profile). Agreement on all of them is evidence, not proof: whether two arbitrary programs are equivalent for all inputs is undecidable in general (Rice's theorem). One mismatch, however, proves they differ.

Theory Theoretical complexity analysis

The code is not executed. Its syntax tree is analysed: loop nesting, halving loops, early exits, recursion (Master theorem), known library costs and memory allocations. The result is a heuristic Big-O estimate for best / average / worst case, with the reasoning and a confidence level.

Measured Empirical runtime measurements

Both algorithms are timed on identical inputs of growing size n and several input profiles (e.g. sorted, reversed, random). A curve fit estimates the growth rate. Measurements depend on the machine, the Python interpreter, constant factors and noise — they illustrate but do not prove asymptotic behaviour.

Architecture: Frontend (HTML/CSS/JS) → Flask API → Analysis service (validation · tasks · functional testing · static complexity · benchmarking · report). User code only runs inside a separate, resource-limited Python process.
